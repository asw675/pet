### 真实证据及限制

- `packages/contracts/src/index.ts` 只有 7 类业务命令及 GET snapshot；尚无 AI/记忆/语音/工具领域 API。
- `packages/app-service/tests/integration.test.mjs` 验证 20 次重启、故障原子回滚、双宠隔离和召回；`packages/domain/test/trip.test.ts` 验证 100 seed、72h 分段确定性。此处确有逻辑闭环，而非纯界面。
- `apps/desktop/src/renderer/control-center/router.ts` 的 10 个路由中，首页/宠物/地图/报告/设置有业务投影；背包/商店/图鉴/聊天/工作台为待开发占位。报告仅最近摘要而非完整历史详情；无素材 CG、无完整装备经济。现有 SVG 是工程占位，不是正式模型资源包。
- 真实 Electron 启动、Windows 真机、ABI、安装包和性能不在既有成功记录中。构建成功与模拟 IPC 测试不是这些平台验收的替代品。

## 后续开发与验收策略

用户决定在产品功能实现达到约 90% 后才进入真实窗口、端到端及 Windows 验收；此前持续开发，按模块保留基础类型检查、单元/数据逻辑自动测试及独立 Git 提交。涉及授权、付费服务或必须由用户操作的技术阻塞时请求确认。90% 指以上产品开发覆盖口径，不是发布验收通过率。

| 工作序列 | 目标（对应 V1.1） |
|---|---|
| 004A–E | 资源包契约/校验 → 渲染语义与命中 → 序列帧及静态降级 → 原子资源/换宠 → CG 历史版本与图鉴（§17） |
| 阶段 B | 完善角色获得/昵称、状态调度、路线、装备、经济、事件/CG 业务（§3–7、18） |
| 阶段 C | 模型 provider、人格、流式对话、逐宠记忆与隐私（§8–9、19） |
| 阶段 D | STT/TTS 抽象与实现、播放队列、打断、静音、嘴型通道（§9、20） |
| 阶段 E | 受控快捷入口、用户授权、使用统计、规则推荐（§10、21） |
| 阶段 F | 功能达到目标后按原 P0/验收矩阵开展实际窗口、系统、发布及回归（§16、22–23） |
