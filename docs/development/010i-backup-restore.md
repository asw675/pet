# 010I 从本地备份恢复存档

日期 2026-11-25。依据 V1.1 §18.5 和 §22。在设置的「本地存档备份」选择 `.sqlite3` 文件并通过原生对话框确认后，本地服务验证备份并自动重启。当前数据库无法打开时，同一入口可在旧进程退出后启动一次恢复进程。设置页可以读取恢复结果。备份包括游戏数据和应用数据库中的偏好，系统凭据保存在独立的本机密钥仓中。

恢复由应用服务执行。它从原生对话框取得路径，复制关闭的备份到应用数据目录的私有暂存区，核对支持版本中的真实库结构、迁移记录、完整性及外键约束。旧版本迁移和游戏启动校验均只操作暂存副本。重启时，Main 等待旧进程退出后才启动替代服务。新服务复核暂存文件摘要，保存原数据库的独立目录项，再以同卷原子替换提交恢复。结果存储在数据目录，进程在提交后中断时也不会重复应用备份。发现当前库仍有 WAL、SHM 或 rollback journal 时保留原库并结束该次恢复。

验证使用合成临时存档，覆盖真实 SQLite 当前版本与 v10 恢复、原始备份及恢复前存档保留、损坏和未来版本拒绝、篡改库结构及暂存文件拒绝、遗留日志处理和替换后的中断重试。端到端传输测试覆盖运行中请求、重启及无法打开原库时从已校验备份冷启动。宿主、preload 和服务客户端测试覆盖焦点授权、选择后确认、无路径的渲染进程接口及等待旧写入进程退出。

本机 Windows 开发环境运行恢复、导出、宿主、preload、设置策略、服务客户端及传输共 7 个测试文件，169 项通过。

恢复要求文件系统支持同卷替换和硬链接。若损坏的原库仍有未清理的日志文件，应用保留该库及其日志原样并中止替换。周期快照见 [010J](010j-periodic-snapshots.md)。断电和 Windows 安装版完整恢复演练待验证。
