# 010J 定期本地存档快照

日期 2026-11-25。依据 V1.1 §18.5 和 §22。应用服务在运行时创建首份已提交存档快照，之后距上一份成功快照满 24 小时再创建下一份。保留最近三份自动快照，为最近状态和两个较早的恢复点留出空间。该周期和保留数量是当前产品默认值，设计文档未指定具体数值。

快照使用手动导出的同一 SQLite `VACUUM INTO` 和只读校验逻辑，由唯一写入进程在权威快照事务结束后运行。成功验证的新文件才会替换最早的自动快照。快照在应用数据目录的 `.pet-snapshots`，随机的目录归属标记限定三个托管文件名，手动导出及迁移前备份不在轮换范围。导出失败会保留已发布快照，运行中的服务一小时后再次尝试。本地游戏存档仍通过原有 SQLite 错误处理与事务保护继续运行。

设置中的存档备份区显示最近一次自动快照和当前生成失败提示。打开恢复对话框时，存在自动快照目录则优先浏览该目录。文件仍由用户选择并在原生对话框确认，随后走相同的备份验证和恢复流程。

本机 Windows 开发环境运行周期快照、恢复、宿主、preload 和应用服务传输共 5 个测试文件，138 项通过。实际 SQLite 测试覆盖已提交 WAL、重复轮询及进程重启无重复写入、三份轮换、磁盘失败时保留已有备份、正常恢复和唯一写入进程的定时调用。断电和 Windows 安装版恢复演练仍需验收。
